# GO Sidecar v0.1 Implementation Plan

**Goal:** Deliver an installable Android v0.1 that captures the current screen on demand and turns it into an editable GO draft without auto-send.

**Architecture:** Native Java Android app with a persistent user-visible overlay foreground service and a separate MediaProjection foreground service. Personal v0.1 accepts the existing API key on-device, encrypts it with Android Keystore, and calls the OpenAI Responses API directly; public/multi-user deployment will move API access behind a backend relay.

**Tech Stack:** Java 17, Android SDK 36, Android Gradle Plugin 8.9+, JUnit, Android Keystore, HttpsURLConnection, OpenAI Responses API.

## Constraints
- Android-first, compileSdk/targetSdk 36.
- No auto-send or accessibility control of third-party apps.
- User-triggered single-frame capture only.
- Explicit preview confirmation before image analysis.
- Existing OpenAI API key is never embedded in source/APK.
- v0.1 work mode is generic visual assistance; Fastwork-specific GO Client logic follows after the visual sidecar is proven.

## Verification
- Pure state, prompt, and JSON extraction logic use RED → GREEN tests.
- GitHub Actions runs `testDebugUnitTest` and `assembleDebug` on every push to the isolated build branch.
- The APK is uploaded as a workflow artifact only after tests and build pass.
